how a thought travels.

From the moment you speak to the moment tällmi shows you people, places, topics and feelings: every step, what it uses, and where the result is kept. All of it runs on your Mac.

the whole pipeline

step by step

1

capture

You press the hotkey (⌃⌥T), use the menu bar, talk to tälli, or type into the composer. While you speak, Apple's SpeechTranscriber shows a live preview of your words. That preview is only shown, never saved: it disappears when you stop. The transcript that is kept comes from Parakeet in step 3.

The microphone writes to recording.m4a in a protected scratch folder. Very short or silent recordings are dropped.

Audio/MicrophoneRecorder · AppComposition/LivePreviewService · Engines/SpeechAnalyzerEngine
2

file the thought

When you stop, the recording moves into a new thought folder in your archive. Every file is sealed with AES-GCM using one archive key that lives in the Keychain. Folder names are random, so a synced archive reveals no dates.

A typed thought skips the recording: its text is there from the start. Either way, tällmi queues its jobs and starts the background work.

Persistence/EntryFileStore · ArchiveCrypto · ADR 0004, 0010
3

transcribe

Parakeet v3 (via FluidAudio, on the Neural Engine) turns the recording into text with word timings, German and English mixed. It decrypts the audio into scratch only, never into the archive.

  • The transcript is saved and seeds your text, but only the first time. After that, the text is yours; nothing overwrites it.
  • Names you taught tällmi (vocabulary, optionally your contacts) are corrected by how they sound, using Kölner Phonetik.
  • No words heard and nothing typed: the thought is discarded.
Pipeline/PipelineRunner.transcribe · Domain/KoelnerPhonetik · Engines/FluidAudioEngine
4

index

The thought's text goes into SQLite. The full-text index (FTS5) uses trigrams, so searching "angst" also finds "Zukunftsangst". This is what makes ⌘K instant and what highlights the matching words.

Persistence/EntryIndex · Migrations (entry_search, trigram)
5

split into passages

The text is cut into passages of about 600 characters (never more than 1200). Blank lines always start a new passage, and sentences are kept whole. Plain rules, no model: splitting by topic may replace this later. Each passage remembers exactly where it sits in your text, so a later match can point at the right spot.

The splitting rule is stored with every thought. Change the setting and every thought is split again.

Domain/PassageSplitter · Persistence/FragmentStore · Pipeline/MeaningSteps
6

embed

Qwen3-Embedding (0.6B, 8-bit, via MLX) turns each passage into a list of 512 numbers that captures its meaning. They live in sqlite-vec, in a table per model, so swapping the model never mixes old and new vectors.

  • Search by meaning: ⌘K blends word matches and meaning (reciprocal rank fusion).
  • Thoughts found only by meaning are labelled related, never presented as answers.
  • Related thoughts next to the one you are reading.
Engines/MLXEmbedderEngine · Persistence/VectorStore · Search/HybridSearch · ADR 0011
7

understand new ADR 0012

Apple's on-device Foundation Model reads the thought and fills a fixed form:

  • concepts: people, places, topics (up to 5) and feelings. Feelings count only when you named them; the prompt forbids guessing from tone. Each one is tied to the exact words in your text.
  • summary: one sentence, in your words' language and from your point of view, only for thoughts of 40 words or more.

Results land in the graph: one concept node per kind and name (the same name is the same concept across thoughts), a mentions link from the passage holding the words to the concept, and a summary node. Each records the model and prompt version that made it. If Apple Intelligence is off, the step waits instead of failing.

Pipeline/UnderstandingStep · Persistence/UnderstandingStore · Engines/FoundationModelsEngine
8

what you see

  • explore views: stack, flow and time today; space later.
  • ⌘K search, with matched words marked in the thought and snippets in the list.
  • related thoughts, from meaning.
  • concept badges on a thought, and a concepts overview that lists every concept and the thoughts that mention it (#52).
Features/ExploreView · FlowView · TimeView · CommandPalette

inside step 7: understand

There is no special training and no hidden logic. Two things happen. First, Apple's on-device model fills in a form whose shape tällmi dictates. Then plain tällmi code checks that form against your words and files the results. The model is asked twice per thought, each time in a fresh session so nothing carries over from one thought to the next.

the form the model must fill

The prompt (German, stored in config as concepts@1) asks for people, places, topics (at most 5) and feelings, but feelings only when you named them. It also asks for "the exact words as they stand in the text" and "no interpretation". It comes with a JSON schema. Apple's model uses guided generation: while it writes, it can only produce output that fits the schema. So kind can only be one of four words, and there are at most 20 items.

{ "concepts": [            // at most 20
  { "name":    "base form, e.g. Heizung",
    "kind":    person | place | topic | emotion,
    "mention": "the exact words from the text" }
] }

The summary prompt (summary@1) asks for one short sentence, first person, in the thought's language, "only what is there: no interpretation, no advice, no feelings that are not named". Its schema is just { "summary": "…" }.

what tällmi's own code does next

  • Check the kind against the kinds enabled in config. Unknown kinds are skipped.
  • Find the mention in your text: every whole-word match, ignoring case. If the words aren't there, the concept is dropped. Nothing is shown that doesn't point back to what you said.
  • Merge by name: the concept's id is kind + lowercased name, e.g. concept:person:kim. The same name in another thought is the same concept. Nothing smarter yet: "Kim" and "Kimmy" stay two people.
  • Link to the passage holding the words, with exact character positions. That is what badges and highlights use.
  • Record provenance: model id and concepts@1+summary@1. A new prompt version makes every thought stale, and the sweep runs them again.
  • Concepts no passage mentions any more are deleted.

a real run

Run today on this Mac with the exact prompts and schema from config, Apple's model, temperature 0.2, three times. This is a sample thought, not one of yours. Its person's name was later replaced with the invented "Kim", positions recomputed.

what the three runs show

  • Names and places are reliable. Kim, Lissabon and Heizung came back every time.
  • Roles are missed or put under the wrong kind. "Vermieter" came back as a topic every time, though the prompt says roles are people. "mein Chef" was never found. Büro and Wohnung were never found as places.
  • The word check works. Run 2 returned the topic "Job", which isn't in the text. tällmi found no such word and dropped it.
  • Feelings vary. "müde" came back in runs 1 and 3, not in run 2.
  • The summary adds things. All three say "müde und genervt", while the thought says "eher müde als genervt". Two add "weil ich den Vermieter nicht anrufe", a reason the text never gives. Nothing checks the summary against your words, which goes against the no-slop rule (ADR 0006).

the job queue and the sweep

Every thought gets one job per step: transcribe, split, embed, understand. Jobs live in the database, so they survive quitting or a crash. tällmi runs one job at a time at low priority, and a step only starts once the earlier steps of that thought are finished.

The sweep runs every 30 seconds. It unloads models that sat idle for a minute, then looks for thoughts whose derived data is out of date and queues them again. That covers:

  • a thought you typed or edited
  • a changed passage setting
  • a swapped embedding model (vectors missing for the new one)
  • a new prompt version for concepts or summary
  • a rebuilt database

On start, jobs that were running when the app quit go back to pending.

every model and prompt comes from config

The code knows engines (FluidAudio, MLX, Apple Speech, Apple Foundation Models), never specific models. Each step asks for a role; the assignments table says which model fills it. Swapping a model means changing a row, not code. Prompts are stored with an id and version, and every result records which ones made it.

Scratch holds the recording while you speak and decrypted audio while it is transcribed; it is cleared on start. Models hold downloaded weights.

nothing leaves the Mac

  • The app has no permission to open network connections at all. No analytics, no crash reports.
  • Models download only when you start it, and each file is checked against a SHA-256 hash in config.
  • Every model in the pipeline runs on device: Apple's speech and language models, Parakeet on the Neural Engine, Qwen3 on the GPU through MLX.
  • The optional MCP server only listens on 127.0.0.1, for apps on this same Mac (ADR 0007).
